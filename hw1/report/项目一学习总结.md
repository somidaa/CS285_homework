## 一、整体任务在做什么

### 1.1 模仿学习（Imitation Learning / Behavioral Cloning）
- 我们**不**自己和环境交互试错（那是 RL），而是直接看专家怎么做，照着学。
- 数据：一堆 `(观测 o_t, 专家动作 a_t)` 配对。
- 训练：训练一个网络 $\pi_\theta$，输入观测、输出动作，让它尽量像专家。
- 本质：**监督学习**。损失就是"网络输出"和"专家标签"的差距。

### 1.2 动作分块（Action Chunking）
普通 BC：看一帧 → 输出一个动作。
动作分块：看一帧 → 一次性输出**未来 K 步**动作，然后**开环执行**这 K 步，中间不再看新观测，执行完再看新一帧。

- Push-T：观测 5 维（T 物体 + 机械臂位置），单步动作 2 维，K=8。
- 所以一次要输出 `2×8 = 16` 个数。

## 二、PyTorch 必知基础（这部分是你最缺的，慢慢看）

### 2.1 Tensor（张量）——就是带形状的多维数组
- `torch.randn(4, 5)`：造一个形状 `(4,5)`、数值服从标准正态的张量。
- 你在项目里所有数据都是张量。**第一件事永远是看 shape**。

```
state:      (B, 5)    # B 个观测，每个 5 维
动作块标签: (B, 8, 2)  # B 个样本，每个未来 8 步，每步 2 维
网络输出:   (B, 16)    # 把 8x2 拍平成 16
```

> 记忆口诀：**网络只能吃"扁的"二维张量**（除了 RNN/Transformer）。三维要自己 reshape 进去、reshape 出来。

### 2.2 nn.Module —— 所有网络的基类
- 你的 `MSEPolicy` 继承 `nn.Module`，它就是"一个网络"。
- 写网络分两步：
  1. `__init__`：声明有哪些层（有哪些参数）。
  2. 前向传播：数据怎么流过这些层。

### 2.3 三个核心层

```python
nn.Linear(in, out)   # y = x @ W + b，全连接层，in维→out维，W和b是要学的参数
nn.ReLU()            # 逐元素 max(0,x)，引入非线性
nn.Sequential(l1, l2, ...)  # 把层串成一条流水线，x 从左流到右
```

**为什么要 ReLU？**
线性层叠多少层都还是线性（$W_2(W_1x+b_1)+b_2 = Wx+b$）。加了 ReLU 这种非线性，网络才能拟合复杂函数。

**为什么输出层不要激活？**
输出是动作，有正有负。加 ReLU 会把负数砍成 0，直接学歪。

### 2.4 build 出来的 MLP 结构
```
输入 (B,5)
 → Linear(5,256) → ReLU
 → Linear(256,256) → ReLU
 → Linear(256,256) → ReLU
 → Linear(256,16)        # 输出层，无激活
输出 (B,16)
```

### 2.5 autograd（自动求导）+ 训练三件套
这是 PyTorch 的灵魂，也是你以后写任何训练都一模一样的模板：

```python
optimizer.zero_grad()   # ① 清空上一步残留的梯度（PyTorch梯度默认累加！）
loss.backward()         # ② 自动算 loss 对每个参数的梯度（链式法则，不用手写）
optimizer.step()        # ③ 用梯度更新所有参数
```

- `optimizer = torch.optim.Adam(model.parameters(), lr=3e-4)`
  - `model.parameters()`：把网络里所有 W、b 收集给优化器。
  - Adam：一种"聪明的"梯度下降，`lr` 学习率控制每步改多大。
- **你永远不自己改参数**，全交给 `optimizer.step()`。

### 2.6 几个易错的点
- `loss` 必须是**标量**（一个数）才能 `backward()`。我们用 `torch.mean(...)` 就是为了把一堆误差平均成一个数。
- 训练用 `model.train()`，测试用 `model.eval()`（虽然这里 MLP 没区别，但要养成习惯）。
- 测试时算动作不要梯度（省显存、快），所以 `evaluation.py` 用 `with torch.no_grad():` 包起来。

## 三、算法一：MSE 策略（逐行对应）

### 3.1 算法思想
最直白：**让网络直接回归专家动作**。损失就是预测动作和专家动作的均方误差。

$$
\mathcal{L}_{MSE} = \frac{1}{B}\sum \| \text{预测动作块} - \text{专家动作块} \|^2
$$

### 3.2 代码逐行

```python
class MSEPolicy(BasePolicy):
    def __init__(self, state_dim, action_dim, chunk_size, hidden_dims=(256,256,256)):
        super().__init__(state_dim, action_dim, chunk_size)  # 必须先调用父类
        layers = []
        d = state_dim
        for h in hidden_dims:
            layers.append(nn.Linear(d, h))   # 全连接
            layers.append(nn.ReLU())         # 非线性
            d = h
        layers.append(nn.Linear(d, action_dim * chunk_size))  # 输出16维
        self.mlp = nn.Sequential(*layers)   # * 是把列表拆开当参数传
```

```python
    def compute_loss(self, state, action_chunk):
        # state: (B,5)  action_chunk: (B,8,2)
        pred = self.mlp(state)                       # (B,16)
        target = action_chunk.reshape(pred.shape[0], -1)  # (B,8,2)→(B,16) 拍平
        loss = torch.mean((pred - target) ** 2)       # 均方误差
        return loss                                   # ⚠️ 一定要 return！
```

```python
    def sample_actions(self, state, *, num_steps=10):
        B = state.shape[0]
        pred = self.mlp(state)                # (B,16)
        return pred.reshape(B, self.chunk_size, self.action_dim)  # →(B,8,2)
```

### 3.3 你踩过的坑（记住这些 = 学会一半）
1. **忘了 `return loss`** → 返回 None，`backward()` 直接崩。
2. **`nn.Relu()` 大小写写错** → 正确是 `nn.ReLU()`。
3. **训练拍平、执行要 reshape 回三维**，因为评估代码用 `action_chunk[chunk_index]` 按步取。

## 四、算法二：Flow Matching 流匹配（重点，最抽象）

### 4.1 为什么需要它？
MSE 有个致命问题：**同一观测，专家可能有多种合理动作（多模态）**。
比如"把 T 推到目标"，专家可能从左边绕，也可能从右边绕，都是对的。
MSE 直接回归，会把"左"和"右"**平均成一个中间动作**——四不像，反而错。

Flow Matching 不直接输出动作，而是**学一个"速度场"**，让我们能从噪声里"生成"一个合理动作。

### 4.2 数学直觉
想象专家动作 $A$ 和一团噪声 $A_0$ 之间有一条"路"。
- $\tau=0$：纯噪声 $A_0$
- $\tau=1$：专家动作 $A$
- $\tau$ 从 0 走到 1，就是从噪声慢慢"变"成专家动作。

线性插值定义这条路：

$$
A_\tau = \tau A + (1-\tau) A_0
$$

网络要学的是：**在任意时刻 $\tau$，沿这条路该往哪个方向走（速度）**。
理论上这条直线的速度恒等于 $A - A_0$（从噪声指向专家）。

### 4.3 训练（compute_loss）
```python
def compute_loss(self, state, action_chunk):
    B = state.shape[0]
    A = action_chunk.reshape(B, out_dim)     # 专家动作块 (B,16)
    A0 = torch.randn_like(A)                # 随机高斯噪声 (B,16)
    tau = torch.rand(B, 1, device=device)   # 随机时间 (B,1)
    A_tau = tau*A + (1-tau)*A0              # 路上某一点 (B,16)

    # 网络输入 = [观测, 路上的点, 当前时间]
    v_pred = self.mlp(torch.cat([state, A_tau, tau], dim=-1))
    v_target = A - A0                       # 真实速度方向
    loss = torch.mean((v_pred - v_target) ** 2)  # 让预测速度≈真实速度
    return loss
```

- `torch.rand(B,1)`：随机时间。形状 `(B,1)` 和 `(B,16)` 广播，每行用同一个 $\tau$。
- `torch.cat([...], dim=-1)`：把三块横向拼成 22 维输入。

### 4.4 推理（sample_actions）—— 欧拉积分
训练好学了速度场，推理时从纯噪声出发，**一步一步走**到 $\tau=1$：

$$
A_{\tau+dt} = A_\tau + dt \cdot v_\theta(\text{state}, A_\tau, \tau)
$$

```python
def sample_actions(self, state, *, num_steps=10):
    B = state.shape[0]
    A = torch.randn(B, out_dim, device=device)  # 从噪声开始
    dt = 1.0 / num_steps                      # 步长 = 1/10
    for i in range(num_steps):
        tau = i * dt                          # ⚠️ 当前位置 0,0.1,...,0.9
        tau_batch = torch.full((B,1), tau, device=device)
        v = self.mlp(torch.cat([state, A, tau_batch], dim=-1))
        A = A + dt * v                        # 沿速度走一步
    return A.reshape(B, chunk_size, action_dim)
```

### 4.5 你踩过的关键坑
- **喂给网络的 tau 是 `i*dt`（当前位置），不是 `(i+1)*dt`（终点）**。喂错时间，网络看到的时刻和实际位置对不上，直接学崩。

### 4.6 为什么效果更好？
从噪声"生成"动作，天然能表达多模态——不同噪声种子会生成不同但都合理的动作，不会像 MSE 那样被迫取平均。这就是 Flow 奖励 0.83 > MSE 0.62 的原因。

## 五、训练循环长什么样（可复用模板）

```python
optimizer = torch.optim.Adam(model.parameters(), lr=config.lr)

for epoch in range(num_epochs):           # 把数据看好几遍
    for state, expert_action in loader:    # 每次取一个 batch
        state = state.to(device)
        expert_action = expert_action.to(device)

        model.train()
        loss = model.compute_loss(state, expert_action)  # 算误差

        optimizer.zero_grad()   # 清梯度
        loss.backward()         # 反传
        optimizer.step()        # 更新

        if step % 10000 == 0:   # 隔很久才评估一次（评估很慢）
```
